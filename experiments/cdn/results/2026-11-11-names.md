# Station and vehicle names against the live iRail API (#248)

Script: `verify_names.py` (needs `fetch_data.py` and `inspect_extensions.py` first). CDN release
`nmbs-sncb-20261111-5c05082d`, live API `https://api.irail.be/v1`, 11 November 2026.

## Stations

716 stations in the API, 748 in the CDN `stations` table (4 only in the API, 36 only in the CDN).

| Comparison | Equal |
|---|---|
| API `standardname` == `stations.name` | 705 / 712 |
| API `standardname` == `stopEnrichment.nameNl` | 555 / 621 |
| API `standardname` == `stopEnrichment.nameFr` | 538 / 621 |
| API `name` (nl) == `stations.alternativeNl`, else `.name` | 701 / 712 |
| API `name` (fr) == `stations.alternativeFr`, else `.name` | 705 / 712 |
| API `name` (de) == `stations.alternativeDe`, else `.name` | 683 / 712 |
| API `name` (en) == `stations.alternativeEn`, else `.name` | 695 / 712 |
| API `name` (nl / fr / de / en) == `stopEnrichment.nameNl / Fr / De / En` | 618, 620, 598, 610 / 621 |
| Coordinates (1e-4 degrees) | 707 / 712 |
| API `id` == `BE.NMBS.` + the number in the IRI | 716 / 716 |

- **`standardname` is `stations.name`.** The 7 differences are spelling: `Amsterdam Centraal` against
  `Amsterdam CS`, `Berlin HBF` against `Berlin Hbf`, `Duesseldorf Hbf` against `Düsseldorf Hbf`, `Lessen` against
  `Lessines` (the API's standard name there is the Dutch one), and a typo the API has (`Reginalbf`).
- The per-language `name` is **not** one column: it is `alternativeXx` where set, else `stations.name`, and that
  still misses 7 to 29 stations, mostly international ones. `stopEnrichment.nameXx` is a worse match for
  `standardname` (it is translated: `Aken Hbf` for `Aachen Hbf`).
- `stopEnrichment` covers 635 stations, `stations` 748; use `stations` as the base.

## Vehicles

Rule tested: split the last segment of `tripEnrichment.vehicleIri` into letters and digits. All 7401 distinct IRIs
fit that shape. Up to 5 vehicles per type that answered on 12 November.

| Type | Checked | Result |
|---|---|---|
| IC, EC, L, P, NJ, OTC | 26 | `name` (`BE.NMBS.` + tail), `shortname` (`IC 2130`), `number`, `type`, `@id` all equal |
| S | 5 | equal **only with a special rule**: the train number is the last four digits, the rest is the line. `S102056` is `S10 2056` (`type` `S10`, `number` `2056`), `S38574` is `S3 8574`. The plain split gave `S 102056`. |
| BUS, EXT, T | 0 | not comparable: the API answers 404 ("Vehicle not found in GTFS data") for EXT and T, and for BUS it resolves the number to a *different* vehicle (`BUS1910` returns `IC1910`) |

- 404s are common for the other types too (for example 8 of 13 `IC` tries): many CDN vehicles are not served by the
  API. That is why the script keeps trying until it has five answers.
- **Vehicle location is not always `"0"`.** The `vehicle` endpoint returns the coordinates of the vehicle's *first
  stop* (31 of 31 checked equal the first stop's station position; none were `"0"`). The `liveboard` and
  `connections` responses return `"0"`, which is what the recorded examples in this repo show. So for the vehicle
  endpoint a station position is exactly what the API gives; elsewhere there is nothing.
