# CDN readers on a Home Assistant Yellow, 2026-11-11

Same benchmark as [`2026-11-11.md`](2026-11-11.md) (`compare_all.py`), run on a real Home Assistant device. This closes the
"Raspberry Pi 4-class" item of [#247](https://github.com/tjorim/pyrail/issues/247).

## Setup

- Device: Home Assistant Yellow with a Raspberry Pi Compute Module 4 Rev 1.1 (4 cores, 3.8 GB RAM), Home Assistant OS, kernel `6.18.59-haos-raspi`, aarch64, Alpine (musl) userland.
- Run inside the SSH add-on container (Alpine 3.24, Python 3.14.10) in a throwaway venv under `/tmp`. Nothing was installed into Home Assistant itself.
- **The device was live**: 10 containers running (Home Assistant core 2026.11.1, Matter, Thread border router, Mosquitto, Tailscale and others), load average about 0.5 to 1.3, about 0.9 to 1.0 GB RAM available with swap in use. So these are numbers under realistic background load, not a quiet bench.
- CPU 900 MHz idle to 1.5 GHz under load (ondemand governor), 51 to 52 °C before and after. Throttling flags were not read (no `vcgencmd`).
- Data: release `nmbs-sncb-20261111-5c05082d`, 4 tables + 8 consecutive connection pages (12 files, 133k rows), every column decoded into Python lists. Same files as the x86 run.
- Wheels: every library installed from a prebuilt `musllinux` aarch64 wheel (`pyarrow` 26.0.1, `arro3-io` 0.9.1, `nanoarrow` 0.9.0, `aiohttp` 3.14.5, `orjson` 3.13.0). No compiler needed.

## GTFS Realtime snapshot (77 KB, 259 trip entities)

`gtfs-realtime-bindings` 3.0.0 + `protobuf` 7.36.2. Which `protobuf` implementation you get depends on the environment:

| Environment | protobuf implementation | Import | Parse (best / median) | Peak RSS |
|---|---|---|---|---|
| Home Assistant core container (its own Python 3.14.10 and `protobuf` 7.36.0) | `upb` (C) | 116 ms | **1.09 / 1.14 ms** | 15 MB |
| Fresh venv on the same device | `python` (pure) | 261 ms | **196 / 200 ms** | 18 MB |

A plain `pip install protobuf` on musl aarch64 resolved to the pure-Python `py3-none-any` wheel (PyPI's binary wheels
did not match this platform; I did not check where Home Assistant's image gets its `upb` build). So inside Home Assistant core the
decoder costs about 1 ms, but a standalone install may fall back to about 200 ms per 77 KB snapshot. That is acceptable
for a feed refreshed about once a minute, but it is the number to keep in mind if the refresh rate goes up. The test ran
in the core container's `/tmp` with the generated `gtfs_realtime_pb2` module copied in, and was removed afterwards.

## Home Assistant core already ships

`protobuf` 7.36.0 (with `upb`), `numpy` 2.3.2, `pandas` 2.3.3 and `pyrail` 0.6.1. It does not ship `pyarrow` (`import pyarrow` fails).

## Not covered

- Throttling counters, and a quiet-device baseline for comparison.
- Journey planning memory and time on this device (#261, see `planner_benchmark.py`).
- armv7 (the Yellow is aarch64). `pyarrow` has no armv7 wheels; this was not re-tested.
- Single-run figures: treat differences of a few milliseconds or megabytes as noise.
